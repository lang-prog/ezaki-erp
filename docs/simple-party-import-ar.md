# الاستيراد المباشر للعملاء والموردين

## الفكرة

هذا المسار لا يقرأ قاعدة البيانات القديمة ولا ينفذ SQL ولا ينقل فواتير أو مخزون أو سندات. البرنامج القديم يجهز ملف JSON صغيرًا، ثم يرفعه المستخدم من صفحة **العملاء والموردين** في البرنامج الجديد، ويقوم النظام بإنشاء الأطراف وأرصدة البداية مباشرة.

## صيغة الملف

```json
{
  "schema_version": 1,
  "cutoff_date": "2026-09-30",
  "parties": [
    {
      "name": "عميل تجريبي",
      "type": "customer",
      "opening_balance": 12500.00,
      "opening_balance_direction": "debit"
    },
    {
      "name": "مورد تجريبي",
      "type": "supplier",
      "opening_balance": 8300.00,
      "opening_balance_direction": "credit"
    }
  ]
}
```

`cutoff_date` هو تاريخ استخراج الرصيد من البرنامج القديم. ينشئ البرنامج الجديد القيد الافتتاحي في اليوم التالي تلقائيًا؛ لذلك يصبح رصيد 30 سبتمبر رصيد بداية 1 أكتوبر.

`opening_balance` مبلغ موجب فقط. في سجل العميل تعني `debit` أن العميل مدين للشركة، وتعني `credit` أن الشركة مدينة للعميل. في سجل المورد تعني `credit` أن المبلغ مستحق للمورد على الشركة، وتعني `debit` أن المورد مدين للشركة. لا تضع الإشارة السالبة داخل المبلغ.

يمكن إضافة `phone` و`email` و`tax_number` و`address`، وكلها اختيارية. يتم قبول `source_id` لتمييز حسابات المصدر المستقلة حتى إذا كان لها نفس الاسم. يسمح النظام بتكرار الاسم عندما تختلف هوية المصدر، كما يقبل `opening_balance: 0` ويضيف الطرف دون إسقاطه.

## ما يحدث عند الرفع

يتحقق النظام من نوع الملف وحجم الملف وصحة JSON والتاريخ والنوع والمبلغ واتجاه الرصيد. إذا وُجد خطأ، لا يتم حفظ أي صف. من شاشة الرفع يمكن اختيار حساب أب مخصص للعملاء، وحساب أب مخصص للموردين؛ يجب أن يكون الأول حساب أصول نشطًا والثاني حساب خصوم نشطًا داخل نفس الشركة. عند تركهما فارغين يستخدم النظام حسابي **العملاء** و**الموردين** الافتراضيين، ثم ينشئ القيد الافتتاحي المتوازن مقابل حساب أرصدة البداية، مع الالتزام بعزل الشركة وصلاحية `parties.create`.

## ما لا يشمله هذا المسار

لا يشمل الاستيراد الحالي المخزون أو الأصناف أو الأنواع أو الأقطار أو فواتير المبيعات والمشتريات أو إيصالات القبض أو سندات الصرف أو النقدية أو البنوك. يمكن تنفيذ أي من هذه المراحل لاحقًا كميزات منفصلة إذا لزم الأمر، دون إعادة إدخال تعقيد محلل SQL إلى هذا المسار.

## التصدير من البرنامج القديم

على البرنامج القديم إنشاء JSON بالحقول السابقة فقط. قيمة الرصيد يجب أن تكون النتيجة النهائية حتى 30 سبتمبر بعد تطبيق معادلة البرنامج القديم، وليس تفاصيل الحركات. قبل الرفع، راجع عينة من العملاء والموردين يدويًا، وتأكد من اتجاه الرصيد وفق التعريف أعلاه.
